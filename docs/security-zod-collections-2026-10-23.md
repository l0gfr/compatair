# Zod collection resource bounds, 23 October 2026

GitHub advisory [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) blocks the publication with Zod 4.4.3 and the legacy Zod 3.25.76 used by Chromium BiDi in Lighthouse. The release severity policy remains unchanged, including for development dependencies.

The direct dependency and the compatible sitemap dependency now resolve to Zod 4.6.7, already used by Astro. The official npm metadata dates this release to 12 October 2026. Its archive SHA-512 and registry signature were verified; the 24-hour quarantine is preserved. No other transitive package is upgraded.

Chromium BiDi 14 uses Zod 3 APIs. Replacing that package with Zod 4 breaks its schemas. A small local backport therefore retains the existing array and set size errors but stops before traversing oversized constrained collections. It covers array maximum/exact length and set maximum/exact size, synchronous and asynchronous parsing, in the ESM and CommonJS runtime files and the accompanying TypeScript source. Valid boundary inputs, custom messages and nested paths are preserved.

This changes the handling of already-invalid oversized input: element preprocessors and refinements no longer execute after the collection exceeds its declared upper bound. It does not invent a bound for unconstrained schemas. The old package also bundles an experimental v4 subtree. Its shared core receives the same early upper-bound checks for arrays, maps and sets in ESM, CommonJS and the accompanying source. A private payload marker prevents the same size error from being emitted again by the older outer check loop. Prefix-only size checks follow the upstream rule: a preceding custom check may rewrite the value, so it prevents the shortcut. Public custom when callbacks also disable the shortcut, preserving their single evaluation on the post-parse value. Legacy v3 records the outcome of its existing size check instead of reading a collection size again, including for Set subclasses with stateful accessors. The verified BiDi consumer resolves the patched v3 entry; application and sitemap consumers use the official corrected v4 version.

The dependency audit separately and mandatorily attests the exact patch bytes, workspace declaration, lock hash, every installed legacy copy, CJS/ESM entry files and both v3/v4 runtime implementations and the real Lighthouse/Puppeteer/Chromium-BiDi resolution. A mismatched, missing or extra vulnerable copy fails publication. The known advisory remains reported as locally corrected only after this attestation passes. The GitHub client preserves the advisory identifier, vulnerable version ranges, first patched versions and exact queried locked versions. Recognition requires the reviewed range < 4.6.6 and first fix 4.6.6: an extension affecting 4.6.7, a changed range, missing range metadata, changed title, URL, package or severity, another advisory, or missing attestation remains blocking. Existing cache/Lighthouse patch attestations remain mandatory.

Regression tests cover upper bounds, absence of per-element work on oversized input, both module systems, asynchronous parsing, nested error paths, tampered bytes/configuration/resolutions and unrelated security advisories. A real clean frozen installation, installed-copy attestations and 75 focused tests passed in the isolated repair probe. The repository tests and publication gates must still pass on the final candidate before deployment.
